P8 Project

Immersive Experiences — Adaptive Multi-Agent Conversation in VR

AAU Medialogy, 8th Semester · Continuation of P7

Introduction

Welcome to the P8 Project page. Building on our P7 work, this semester explores a real-time, locally executed multi-agent conversational system in VR, with a focus on adaptive turn-taking, non-verbal behaviors, and low-latency interaction.

The current prototype centers on an interview scenario where a user interacts with LLM-driven NPC agents inside a Unity environment, supported by a backend that handles speech recognition, prosody analysis, language generation, and speech synthesis.

About the project

The system pairs a Unity VR client (HDRP, XR rig, Reallusion CC characters) with a backend stack that orchestrates speech-to-text, dialogue, prosody, and speech output for one or more NPC agents. All inference runs locally to keep latency low and protect user privacy: no conversation audio or transcripts leave the machine by default.

A typical session is an interview: the user wears the headset, speaks to one or more NPC interviewers, and receives spoken, animated, and gaze-aware responses. The system also supports backchannels (e.g. short acknowledgments like "mhm", nods) and an evaluator module that scores the interview after it ends.

Objectives

  • Reduce end-to-end response latency for multi-party VR conversations
  • Coordinate turn-taking, backchannels, and gaze across multiple NPCs
  • Run STT, LLM, and TTS locally to preserve privacy
  • Provide automated, structured evaluation of interview sessions

System architecture

The prototype is split into a Unity client and a local backend:

  • Unity VR client (P8-IMMEXP26/) — HDRP scene, XR rig, Reallusion CC characters, NPC behavior scripts, animation and gaze controllers, and a WebSocket client
  • Bun WebSocket server (server/index.ts) — the main orchestrator, routing speech, dialogue, and control messages between Unity and the other services
  • Prosody server (server/prosody_server.py, prosody_core.py) — Python service that analyzes audio features used for turn-taking and backchannel decisions
  • Ollama — runs local LLMs with custom Modelfiles (server/modelfiles/Modelfile.interviewer) to drive interviewer NPCs
  • Whisper.cpp — local speech-to-text using ggml-base.en.bin in Assets/StreamingAssets/Whisper/
  • ElevenLabs / Piper TTS (server/elevenlabs.ts, Assets/Piper/) — speech synthesis, with a local Piper option for the fully offline path
  • Evaluator (server/evaluator.ts) — post-session module that scores the interview based on the conversation log

Key features

  • Adaptive turn-taking — prosody-aware decisions about when an NPC should start, hold, or yield the floor
  • Backchannels — short verbal and non-verbal acknowledgments with cooldowns and action variety
  • Gaze state machine — NPCs direct attention to the active speaker and other agents in a believable way
  • Phased interview flow — structured stages (intro, questions, wrap-up) governed by an activity-style flow
  • Local-first inference — STT, LLM, and (optionally) TTS all run on the same machine
  • Automated evaluation — interview transcripts are scored after the session ends; unit tests cover the evaluator in evaluator.test.ts

Tech stack

  • Engine: Unity 6000.3.6f1 (HDRP, XR)
  • Backend runtime: Bun + TypeScript
  • Audio analysis: Python (prosody)
  • LLM: Ollama with custom Modelfiles
  • STT: whisper.cpp (ggml-base.en)
  • TTS: ElevenLabs and Piper
  • Characters: Reallusion Character Creator / iClone tools
  • Containerization: Docker Compose (Bun + Python services)
  • CI: GitHub Actions for backend tests
